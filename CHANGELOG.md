All notable changes to cephalo are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Dates follow ISO 8601 (`YYYY-MM-DD`).

## [1.0.0] — 2026-09-24

**First public release.** A browser-based setup assistant, a documentation and utility-script hardening pass, removal of hard-coded formatting rules from three agent definitions, a pre-publication review sweep (license text, distribution docs, GitHub project files), and a pre-publication security pass (see **Security** below). A final pre-release audit then fixed bugs in both setup scripts, the setup assistant and all five utility scripts, closed further security and privacy gaps, brought workflows, checklists, templates and agents in line with the styleguide-only principle, and widened CI coverage.

### Added

- **GitHub project files** — a minimal CI workflow (`.github/workflows/ci.yml`: script syntax/compile checks, workflow-YAML validation, and non-interactive setup smoke runs on Ubuntu and Windows), issue and pull-request templates aligned with `CONTRIBUTING.md`, and a `SECURITY.md` describing scope and the private reporting channel.
- **`docs/setup-wizard.html`** — a self-contained, offline setup assistant. Pick work type, structure, scaffolding, and platform, and it builds the exact `setup.ps1` / `setup.sh` command and previews the folder structure that will be created. It also offers a one-click **Download launcher** button that saves a small, preconfigured start script (`cephalo-setup.cmd` on Windows, `.command` on macOS, `.sh` on Linux) — save it into your cephalo folder, then unblock it once in its Properties and double-click it (Windows, which blocks a downloaded launcher until then) or run it with `bash` from a terminal (macOS/Linux: a downloaded file is not executable, and macOS blocks a double-click on it). Opened from the cephalo folder on macOS or Linux, the page puts a `cd` into that folder before `bash setup.sh`, so the command can be pasted into any terminal window, and the launcher also runs from the Downloads folder. Static HTML with no dependencies or network access; it generates commands and launcher scripts but never runs anything itself. Linked from `README.md` and `docs/QUICKSTART.md`.
- **`.gitattributes`** — keeps the shell scripts LF in every checkout (`*.sh text eol=lf`), so a Windows clone with `core.autocrlf=true` no longer breaks `setup.sh` and the helper scripts under WSL or Git Bash. Both setup scripts now append their Git LFS rules to an existing `.gitattributes` (without duplicates on re-runs), so generated projects keep them.
- **`templates/styleguide.md`** — slots for rules the agents already defer to: `title_page.*`, `captions.*` (table, figure and source placement), `numbers.decimal_separator`, `numbers.p_values`, `document.figure_resolution` and `headings.toc_emphasis` (table-of-contents levels).
- **CI coverage** — the Ubuntu job now also runs the utility scripts on generated files (exit codes, one-line errors, hyphenation, disguised ZIPs and path traversal), checks agent definitions, workflow references and the archive-extraction rule, re-runs setup to guard state files and the generated `.gitignore`/`.gitattributes`, tests more invalid arguments, menu hints and step numbering, the LF rule in an autocrlf clone, and the setup assistant's JavaScript, whose generated commands are also run through bash and PowerShell with hostile target paths. `bash -n` now checks each shell script (it had parsed only the first). The Windows job now also checks `setup.ps1` under Windows PowerShell 5.1 for its UTF-8 BOM, flat and multi-project runs, the Git LFS rules, a re-run that keeps an edited `00_Status.md`, a target with `[ ]` in its name and a re-run inside it, and exit 2 on closed stdin. A final release sweep added checks that `--target` copies leave out the template's `.github/`, the setup-assistant launcher and virtual environments and refuse a non-empty target, that the data ignore rules and the menu-chosen Flat-only rule hold, that `setup.sh` and `setup.ps1` (under PowerShell 7) scaffold identical projects in all 22 combinations, that the downloadable `.sh`/`.command` launcher passes the target unchanged and reports a failed setup (the Windows `.cmd` launcher is checked as text), that the wording of the embedded README/QUICKSTART copies matches their Markdown sources and relative Markdown links resolve, that workflows reference existing checklists, scripts, documents and base workflows, that each orchestrator may call every agent its workflows declare, that every styleguide key named in agents, checklists, workflows and docs has a slot in the template, and that the archive-extraction guard also knows `python -m zipfile`, `ZipFile.extract()`, `7za`/`7zz` and .NET `ExtractToDirectory`. The utility-script fixtures also cover the citation forms `bibliography_check.py` recognizes, footnote reading in `abbreviations_extract.py`, the unpacked-size cap and symbolic-link entries. A new job runs `setup.sh` and the shell scripts on macOS (`/bin/bash` 3.2, BSD tar) and under Windows Git Bash; the Windows job checks `setup.ps1`'s argument validation; and CI checks that both setup scripts update an existing project the same way. CI uses `actions/checkout@v5` and `actions/setup-python@v6`, which run on Node.js 24. A follow-up round added checks for the setup fixes below (a failure inside a function reported once, also under macOS bash 3.2; Ctrl+C during a `--target` copy; a dragged path at the target prompt; an empty `-Target`; the pause before an error exit; a folder inside the template at the target prompt asked for again, also under macOS bash 3.2 and Windows PowerShell 5.1), for the new script cases, and a first test of the pdftotext-only mode of `extract_styleguide.sh`; two checks written as `a && b` lists in mid-step, whose first part could not fail the step, were split. A release review added pipefail to the Ubuntu job's steps (a failing `setup.sh` piped into `tee` or `sed` went unnoticed), checks for the framework files named in the free text of workflows, agents, checklists and templates, a code-fence rule in the archive-extraction guard that also covers a block nested in a longer fence, fixtures for the remaining citation forms `docs/scripts.md` lists and for a German genitive, `setup.ps1` with a target on a drive that does not exist, both setup scripts started from a project with a new target, and fixtures for an ASi-declared link, an existing `<document>.new` and archives with a corrupt LZMA member or a nameless entry.

### Fixed

- **`LICENSE`** — restored the verbatim Apache-2.0 text: Section 6 was missing "reasonable and customary use in", and Section 9 read "Accepting Warranty or Support" instead of "Accepting Warranty or Additional Liability" (heading and closing sentence). The shipped file now matches the canonical text from apache.org, with only the appendix copyright line filled in.
- **`bibliography_check.py`** — middle authors of 3+-author entries (`Dawson, R., Ellis, S., & Fowler, T.`) are now extracted, removing a false positive where a visibly listed co-author was reported as "cited but not in bibliography".
- **`setup.ps1`** — when all three configuration values are supplied as parameters, they are validated **before** the `-Target` template copy: a typo like `-Structure Langform` now fails fast instead of leaving a stray template copy at the target (which then also blocked the corrected non-interactive retry with "Refusing to copy into non-empty directory").
- **`setup.sh`** — the "Next steps" summary numbers its steps contiguously on full-scaffolding runs (previously it printed 1, 2, 4).
- **Both setup scripts** — interactive menus now answer invalid input with "Please enter a number between 1 and N." instead of silently re-prompting.
- **`docx_postprocess.sh` / `extract_styleguide.sh`** — both understand `-h`/`--help` now; the pdftotext-only fallback of `extract_styleguide.sh` distinguishes ZIP archives disguised as PDFs from merely corrupt files; `docx_postprocess.sh` no longer reassigns the standard `TMPDIR` environment variable for its work directory.
- **`setup.ps1`** — `.\setup.ps1 ... -Target ...` no longer requires answering interactive prompts when `-NonInteractive` is passed; documented non-interactive examples in `README.md` and `docs/QUICKSTART.md` now include the switch so they run unattended as advertised.
- **`setup.sh`** — supplying all three positional arguments (work type, structure, scaffolding) no longer asks for confirmation, and the run succeeds with closed stdin (CI, scripts), matching the documented examples. In a terminal, a `--target` run still offers to delete the template folder at the end.
- **`docx_postprocess.sh`** — no longer requires `zip` (only `unzip` and a working Python 3 are needed; re-zipping was already done with Python's `zipfile` module, so the dependency check was a leftover). This removes the most common Windows/Git Bash onboarding blocker for this script. The interpreter check now probes for a *working* Python under both `python3` and `python`, catching the case where `python3` resolves to a dead Microsoft Store app-execution-alias stub. Auto-hyphenation detection now correctly treats an explicitly-disabled element (`w:val="0"`/`"false"`/`"off"`) as disabled and rewrites it, instead of mistaking it for already-enabled.
- **`abbreviations_extract.py`** — footnotes and endnotes are now actually read (previously silently skipped due to an unsupported python-docx access pattern). Dotted abbreviations no longer lose their last segment (`U.S.A.` now normalizes fully to `USA` instead of truncating to `US`). All-caps acronyms containing digits, or up to 8 characters long, are now recognized (`B2B`, `CO2`, `5G`, `BENELUX`).
- **`bibliography_check.py`** — surnames starting with Ä/Ö/Ü are now recognized on the bibliography side, matching the in-text side (previously such entries were silently invisible to the check). Year-suffix citations (`Schulz (2022a)`, `(Wagner, 2022a)`) are now recognized in narrative form, not just parenthetical. Name-prefix matching now also covers `van den`, `ter`, and `ten`. The German citation lead-words `siehe` and `nach` are now recognized alongside the already-supported `vgl.`/`cf.`/`see`. `--help` now prints usage instead of a confusing "file not found" error; a corrupted or non-DOCX file now produces a clear one-line error instead of a raw traceback.
- **`cross_session_audit.py`** — main-worktree detection now trusts git's own guarantee (the first entry of `git worktree list --porcelain` is always the main worktree) instead of an unreliable path-based heuristic, fixing misidentification when the repository's own path contains a `worktrees` path segment. A nonexistent or invalid `--repo-root`, or a missing `git` binary, now produces a clear one-line error instead of a raw traceback. Operational errors (e.g. not a git repository) now exit with code 2, distinct from exit code 1 for findings, so CI/hooks can tell the two apart. The reference-validation layer now also recognizes `workspace/...`-prefixed paths, covering flat-structure projects.
- **`setup.sh`** (pre-release audit) — unknown or misspelled options (`--taget`), an empty `--target=` and a fourth positional argument now exit 2 before anything is created instead of setting up the template folder itself; `-h`/`--help` works anywhere. The target is canonicalized before the inside-template check: `--target ../Thesis` is no longer falsely rejected, and targets that reach into the template through a symlink or a `..` detour are refused instead of copying the template into itself. Only `~` and `~/` are expanded (`~Documents/Thesis` no longer becomes a sibling of the home folder). A failing template copy shows tar's error and exits 3. A failing `git lfs install` only warns. "Proceed?" accepts `Y`/`yes`/`J`/`ja`. Ctrl+D selects the safe default at the location, target-path and `[y/N]` prompts; at a menu or at "Proceed?" it cancels with exit 2. `--target` copies skip `venv/` and nested virtual environments. An invalid work type lists the valid options readably, and after a multi-project setup the summary says to open a sub-project, not the root. After a `--target` run, the summary names the project folder and prints a `cd` line: the calling shell is still in the template folder, which the steps ("Open this directory", `git add .`) do not mean and which the same summary suggests deleting.
- **`setup.ps1`** (pre-release audit) — the template check now also requires `setup.ps1` itself and real `.claude`/`templates` directories, so running the script by path from the user profile (which often has `.claude\` and a `Templates` folder) no longer scaffolds into the home directory. With `-NonInteractive`, missing values are rejected (exit 2) before the `-Target` copy. A relative `-Target` is resolved against the current PowerShell location, not the directory PowerShell was started in. Copying into a confirmed non-empty `-Target` no longer deletes the user's own `venv`/`.venv`/`__pycache__` folders or `.claude\settings.local.json`. Closed stdin without `-NonInteractive` exits 2 instead of looping forever or reporting "Cancelled.". "Proceed?" accepts `yes`/`ja` like `setup.sh`. The template is copied to `-Target` only after "Proceed?" (as in `setup.sh`), so answering "n" no longer leaves a full copy behind that blocks the corrected retry, and the summary shows the target. Paths containing `[ ]` (e.g. `Thesis [final]`) are no longer read as wildcard patterns; such a `-Target` failed with exit 3 after the copy. On Windows PowerShell 5.1, which resolves relative paths wrongly in such a folder and cannot even start in one, the structure, state files and Git repository are now created through absolute paths, and a re-run inside such a project finds the template again (checked with a Windows PowerShell 5.1 smoke test). A directory or file that cannot be created now stops the setup with the error and exit 130 instead of ending in "Setup complete" with exit 0.
- **Both setup scripts** — the setup-assistant launcher (`cephalo-setup*`, also when the browser renamed a second download) and the template's own `.github/` are no longer copied into a `--target`/`-Target` project; the launcher contains the absolute path it was generated for, and `.github/` would run cephalo's CI in every thesis repository pushed to GitHub (`docs/git_introduction.md` says to delete it for in-place setups).
- **`docs/setup-wizard.html`** — the Windows launcher no longer swallows the closing quote and `-NonInteractive` when the target ends in a backslash, and it switches to UTF-8 (`chcp 65001`) so targets with umlauts are not mangled into a different folder. Targets starting with `~-`, `~+` or `~<digits>` are quoted in the bash command. The launchers report a failed setup instead of "Done". After back/forward navigation the command follows the options the browser restored. The embedded README and QUICKSTART are re-rendered from the current Markdown, without the README's link to the wizard itself, which was dead from `docs/`.
- **`docx_postprocess.sh`** — Word-saved documents no longer fail with "ZIP does not support timestamps before 1980" in time zones such as Asia/Singapore; `<w:autoHyphenation/>` is inserted at its schema position (after `<w:defaultTabStop/>`); a failed re-zip no longer leaves a partial `<document>.docx.new` behind. An existing element in open/close form (`<w:autoHyphenation ...></w:autoHyphenation>`) is recognized instead of duplicated, and a document whose settings element cannot be located (e.g. a namespace prefix other than `w:`) now fails with an error instead of reporting "Auto-hyphenation enabled." unchanged. `.DOCX` is accepted, and passing more than one file (e.g. a glob) is refused instead of silently processing only the first. The patched file keeps the original's permission bits instead of becoming readable by everyone.
- **`extract_styleguide.sh`** — a corrupt, encrypted or unsupported ZIP disguised as a PDF is reported for that file and the run continues; a PDF that pypdf cannot read on any page (e.g. AES-encrypted) is reported with the real error and handed to `pdftotext` instead of being called "scanned". `pdftotext` is called with `-enc UTF-8`: the xpdf build (common on Windows) writes Latin-1 by default, which crashed the run on the first umlaut when pypdf was missing. `.txt` files inside a disguised ZIP that are not UTF-8 are read as Windows-1252 instead of losing their umlauts. Text files in the output directory that a run did not write (left over from an earlier run) are listed, so stale guideline text does not reach the style-resolver unnoticed.
- **`docx_postprocess.sh` / `extract_styleguide.sh`** — the interpreter probe also tries the Windows `py` launcher, which a default python.org install puts on PATH instead of `python`.
- **`abbreviations_extract.py`** — acronyms in footnotes/endnotes that Word split across runs are no longer cut apart (`UNESCO` became `UNES` + `CO`); every unreadable input gives a one-line error; the common-abbreviation filter compares case-sensitively, so real acronyms such as `MR`, `NO` or `CO` are no longer dropped because of entries like "Mr", "no" or "Co" (all-caps forms such as `PHD` are now listed too); decomposed umlauts are normalized (`ÖPNV` no longer becomes `PNV`).
- **`bibliography_check.py`** — every unreadable input (a ZIP that is not a Word file, a damaged document, a directory) now gives one line and exit 2, never a traceback or exit 1, which means findings. Recognized now: narrative citations with a page locator (`Müller (2020, S. 15)`, `Smith (2020: 15)`), `u. a.` like `et al.`, typographic apostrophes (`O’Brien`) and letters of any script after a surname's first letter (the first letter stays A–Z or Ä/Ö/Ü), name particles and capitalized lead words (`(Vgl. Smith 2020)`) in parentheses, slash-separated authors in parentheses, and possessives (`Smith's (2020)`). Months and structural words in parentheses (`(März 2021)`, `(Tabelle 3, 2020)`) and prose fragments (`(eigene Darstellung, 2024)`, `Deutschland (2020: 5,9 %)`) are no longer reported as authors, while acronyms and surname-like words in parentheses still count. Text is NFC-normalized; `--help` works under `python -OO`. The bibliography now ends at the next top-level heading that is not itself a bibliography heading (an appendix, the declaration of authorship): a signature line such as `Ort, Datum` is no longer reported as an uncited author, and citations in the appendix count. Of several matching headings the highest-level one starts the bibliography, so a body sub-heading such as `3.2 Sources` no longer does.
- **`cross_session_audit.py`** — a worktree that cannot be inspected (dubious ownership, corrupt index, unreadable) or an unwritable `--report-file` now gives a one-line error and exit 2 instead of a "clean" result or a traceback with exit 1. Run from a git hook, it no longer passes the hook's `GIT_DIR`/`GIT_INDEX_FILE` to its git calls; it reads other worktrees with `git --no-optional-locks status` so it does not take their `index.lock`; references into any two-digit `NN_` directory are checked; `python -OO` no longer crashes it. File names with umlauts appear as they are instead of as octal escapes, and a quoted source line that is itself a table row no longer splits the dangling-refs table.
- **Setup scripts** (final review) — `setup.sh` applies the Flat-only rule also when the work type is chosen in the menu and the structure came from the command line, and its hint keeps `--target`. `setup.ps1` reports a failed `git init` or `git lfs install` as failed instead of as success, and copying into a non-empty `-Target` no longer overwrites the project's `.claude/settings.local.json` or copies the template's `.claude/worktrees` (like `setup.sh`).
- **Utility scripts** (final review) — `cross_session_audit.py` no longer audits its own `--report-file` (also one in a folder the run creates, or with a space in its name) or earlier reports kept in the repository, which made the findings grow on every run. `docx_postprocess.sh` works with an exported `CDPATH`. `abbreviations_extract.py` reads footnotes and endnotes with python-docx 1.0.0 too.
- **Workflows** — `presentation_3agent.yaml` exports the PDF for the three-way check with PowerPoint or LibreOffice (python-pptx cannot render a PDF) and describes the number comparison as manual; in `seminar_2agent.yaml` the source-verifier reads the original quotes in `workspace/state.md`, since that workflow leaves the extracts folder empty.
- **`docx_postprocess.sh`** (release sweep) — under Git Bash, a document with `[ ]` in its path ended in a traceback: the paths passed to Python are now converted with `cygpath` (also in `extract_styleguide.sh`). A document whose name contains `[ ]`, `*` or `?` is unpacked from a copy with a fixed name: unzip read the name as a wildcard pattern, so for `Chapter [2].docx` next to `Chapter 2.docx` the script patched the other file and moved it over the user's document, with exit 0. A name starting with `-` works, and "Auto-hyphenation enabled." is printed only after the document has been replaced. A read-only document is replaced without a question in a terminal (`mv` asked, and on macOS reported success when the question was declined; the document stays read-only), and for a symbolic link the document it points to is patched instead of the link being replaced by a patched copy.
- **`extract_styleguide.sh`** (release sweep) — a PDF with pages on which pypdf's text extraction fails with an error gets a warning with the page count and exit 1, instead of OK with the rules on those pages missing (a page whose content pypdf skips with only a log message still counts as read); an unreadable or image-only PDF inside a disguised ZIP counts as an error of the archive; an output file name over the file-system limit is reported and the run continues instead of ending in a traceback. The pdftotext-only mode (no Python) reads a linked PDF and a guidelines folder given as a link like the Python path; it had skipped a linked PDF without a word and found no PDF in a linked folder.
- **`bibliography_check.py`** (release sweep) — entries added to `BIBLIOGRAPHY_HEADERS` match in the documented exact spelling; heading-styled sub-headings inside the bibliography (`Gesetze, Verordnungen`) are no longer read as uncited authors; a bibliography from which no author-year entry can be read (numeric styles such as `[1] J. Smith, ...`) stops with exit 2 instead of "passed"; `Jones' (2020)` is recognized like `Smith's (2020)`; `O'Brien` and `O’Brien` count as the same name. Entries led by a capitalized name particle (`De Vries, R. (2018)`, `Van der Berg, J.`) are checked and count as cited when the name appears in the text, so an uncited one is no longer skipped silently; `(vgl. auch Müller 2020)` and `(see also Smith 2020)` count for names the bibliography lists; co-authors after `/` or `;` with full given names (`Müller, Hans/Schmidt, Karl (2019)`) are read from the list of names that starts the entry, so `(Müller/Schmidt 2019)` no longer reports Schmidt as missing; `(von Mai 2020 bis Juni 2021)` is no longer read as a citation of "Mai". `zit. nach` is also read after the primary source (`(Weber 1922, zit. nach Keller 2018)`: Keller was reported as uncited), `Müller (2020: 15 f.)` like the comma form, and three or more authors named in a citation (`Dawson, Ellis und Fowler (2018)`, `(Dawson/Ellis/Fowler 2018)`), where the first was reported as uncited (a listed name counts when an entry starts with it, so a list in prose such as `(Juni, Juli und August 2020)` reports nothing). Entries `Ders. (2021)` / `Dies. (2020)` stand for the author above instead of counting as authors "Ders"/"Dies", and a body paragraph that reads just `Literatur` no longer starts the bibliography before a bibliography heading styled Heading 1.
- **`cross_session_audit.py`** (release sweep) — phase and sub-project `README.md` files are checked for dangling references (only the top-level framework docs are skipped), and a worktree whose folder is missing (moved, unmounted) exits 2 instead of counting as clean. In a bare repository the reference check (Layer 2) is skipped: with worktrees made inside the bare folder, it had read their files and reported existing references as dangling.
- **`abbreviations_extract.py`** (release sweep) — subscript digits are read as digits (`CO₂`, `PM₁₀` were dropped without a trace), and the output says to run it on a copy without the list of abbreviations, since every listed entry is otherwise always found. A table with an irregular vertical merge (converter output) is read instead of ending in a traceback.
- **Setup scripts** (release sweep) — a template update (`--target`/`-Target` into an existing project, confirmed at the prompt) keeps the project's own `.gitignore` and `.gitattributes` and only appends the template rules they lack; before, both were replaced silently, so rules the user had added (e.g. for interview transcripts) were lost. A multi-project main work gets the `data/processed/.gitkeep` placeholder too, and `.gitignore` ignores Claude Code's `.claude/worktrees/` and `.claude/settings.local.json` in every folder, so a sub-project's local settings are not staged by `git add .`. `setup.sh`: the Flat-only hint no longer suggests an unvalidated scaffolding value; a `.git` file (worktree, submodule) counts as an existing repository; a target holding only `.DS_Store`, `Thumbs.db` or `desktop.ini` counts as empty (a folder made in Finder was refused); the `rm -rf`, `Use:` and `Run:` hints are single-quoted like the `cd` line (a `$` in a folder name changed the pasted path); the template folder is recognized under another letter case of its path, so on macOS and Git Bash it is no longer copied into itself. `setup.ps1`: a target holding only `Thumbs.db`, `desktop.ini` or `.DS_Store` counts as empty, as in `setup.sh`; failed deletions of the template folder and failed folder creations reach their error handling instead of reporting success; a quoted path pasted at the target prompt (Explorer's "Copy as path") is accepted; a trailing backslash is dropped from `-Target`, which made `git init` fail for a target with a space on Windows PowerShell 5.1. In a follow-up round: `setup.sh` reports a failure inside a function (a folder that cannot be created) with "Setup exited unexpectedly" and pauses, also under macOS bash 3.2; Ctrl+C during a `--target` copy names the partly set-up folder to delete (the same command would refuse it), and Ctrl+C after the setup completed (e.g. at "Delete it now?") no longer reports a cancelled setup and exit 130; a folder dragged into the terminal at the target prompt (quoted, also with an apostrophe in the name, or shell-escaped as `My\ Thesis`) is the folder meant, not a new one named `My\ Thesis`. Both scripts wait for Enter before the error exits a double-clicked run can reach (a failed copy of the template, for example; the window closed at once), `setup.sh` only in interactive runs. In `setup.sh`, Ctrl+C at such a pause (in Git Bash also a habit for copying the text) closes like Enter, with the run's exit code; it had reported a cancelled setup, advised a re-run and waited a second time. `setup.ps1` rejects an empty `-Target` (an unset variable) instead of setting up the template folder itself. At the target prompt of both scripts, a folder inside the template, such as a bare folder name, is refused with an explanation and the prompt asks again; the run had ended with an error that advised running without `--target`/`-Target`, which the prompt does not use.
- **`docs/setup-wizard.html`** (release sweep) — the Windows command drops the double quotes of a path pasted with "Copy as path", as the `.cmd` launcher already did, and the note for a blocked script points to `Set-ExecutionPolicy -Scope Process -Force` instead of `powershell -File`, which mangled a target ending in a backslash.
- **Setup scripts** (release review) — a template folder that cannot be deleted completely at "Delete it now?" (a file without write access, a folder still open in another window) no longer turns a completed `setup.sh` run into "Setup exited unexpectedly" with exit 1: it says what is left, and the run ends with exit 0. `setup.ps1` first moves the process working directory to the project, since Windows does not delete a folder that is a process's working directory (the contents were deleted, the folder was not). `setup.ps1` asks again for a target on a drive that does not exist and ends a `-Target` there with exit 2, instead of reporting a cancelled run (exit 130), and prints its `Remove-Item` and `Run:` hints with single-quoted paths (a `$` in a folder name made the pasted command act on a different folder). `setup.sh` refuses a `--target` that is a broken link with exit 2 instead of "Setup exited unexpectedly", deletes the template folder itself when it was entered through a symbolic link (it removed only the link and still reported the folder as deleted), and names git-scm.com and git-lfs.com for a missing Git or Git LFS. Started from a project folder (one set up in place earlier) with a `--target`/`-Target` that is not empty, both scripts stop with exit 2 before copying: the project's own `00_Status.md`, `styleguide.md` and chapters replaced the target's, although the warning before the copy said such files are kept.
- **`docs/setup-wizard.html`** (release review) — the Windows launcher opens its folder with `pushd` (and releases it with `popd`), so it also works in a folder on a UNC path (redirected Documents, network share), where `cd /d` failed and the launcher claimed it was not in the cephalo folder; the `.sh`/`.command` launcher runs `bash ./setup.sh`, so it no longer fails with exit 126 on a noexec mount or a FAT stick. On a phone-width screen the page no longer scrolls sideways: a long command widened the whole page instead of scrolling inside the command box. ### Security

- **ZIP extraction is routed through `scripts/extract_styleguide.sh`** in `research-agent.md` and `style-resolver.md`. Both previously instructed a bare `unzip`, bypassing the script's `safe_extract_zip()`, which rejects entries carrying absolute paths or `..` components. A prepared archive — a style guide downloaded from anywhere — could otherwise have written outside the target directory. The agents and `checklists/precheck.md` now also rule out every other extractor (`tar`, `7z`, Python `zipfile`, PowerShell `Expand-Archive`), the research-agent runs the script on a scratch folder with an explicit output folder, and CI guards against a regression.
- **Prompt-injection guardrails** added to all ten agent definitions: source and guideline content is material to quote and summarize, never a directive, and the same holds for the extracts, data files, handovers and agent reports the other agents read. Text inside a PDF, ZIP, or e-book can be written to read like an instruction addressed to the agent; the agents now record such text as a flagged note and continue the original task instead of acting on it. `style-resolver.md` lists it as a labelled "not a rule" open question, never in a rule section of `styleguide.md`; `source-verifier.md` labels it as instruction-like content rather than a citation issue. `SECURITY.md` names this risk, but no agent definition had previously addressed it.
- **`requirements.txt` gained upper bounds** (`python-docx>=1.0.0,<2.0`, `pypdf[crypto]>=6.0.0,<7.0`). An open range would silently pull in a new major release that changes the APIs these scripts rely on. The pypdf floor is 6.0, which caps decompressed stream size: with an older pypdf already installed, pip kept it, and a crafted guideline PDF could exhaust memory.
- **`docs/setup-wizard.html`: PowerShell quoting** — the generated command now also doubles the typographic single quotes U+2018–U+201B, which PowerShell treats as quote characters. A target containing one could end the quoted path and run the rest of the field as PowerShell commands; an ordinary folder name with an autocorrected apostrophe (`O’Brien`) broke the command.
- **`docx_postprocess.sh` refuses documents containing symbolic links.** unzip restores symlink entries, so a crafted `.docx` could make the re-zipped document embed arbitrary local files (e.g. an SSH key) or make the settings patch write outside the work directory. The entries are checked in the archive before unpacking: under Git Bash, unzip turns a link entry into a copy of its target by default, which a check on disk afterwards would miss.
- **`extract_styleguide.sh` caps disguised ZIPs** at 512 MiB unpacked and 10,000 entries ("Blocked (security)"), so a small crafted archive can no longer unpack to more than that (a text member close to the cap is still read into memory whole, which takes several GiB).
- **Personal data in generated projects** — `.gitignore` (and the copy both setup scripts write) now keeps all of `data/raw/` and `data/processed/` out of Git, as the workflows promise, instead of only `*.csv`/`*.xlsx` and `*_personal*`/`*_identified*` names (interview transcripts or SPSS files could be committed); the `data/processed/.gitkeep` placeholder is now actually committed, in multi-project main works too. LibreOffice lock files (`.~lock.*#`, which record user and host name) and Word `~WRL*.tmp` files are ignored too.
- **Setup: no deletion of a project** (release review) — started from a project (set up "Here" earlier) with a new target, both setup scripts offered to delete that folder as "the original cephalo template folder", and the copy leaves out `.git/`: answered with y, the project's whole Git history was gone. A folder with `00_Status.md`, `00_Shared_Materials/`, `workspace/` or `styleguide.md` is now kept, with a note.
- **`docx_postprocess.sh` also refuses links declared in Info-ZIP's ASi extra field** (release review), whose mode unzip applies even when the entry's attributes show none: under Git Bash, unzip writes a copy of the link's target, which the check after unpacking cannot see.
- **Personal data** (release review) — `docs/git_introduction.md` says that a cloud sync of the project uploads `data/raw/` and `data/processed/` despite `.gitignore`, and `data-agent.md` keeps the pseudonymization key out of the repository.
- **CI** runs with a read-only `GITHUB_TOKEN` (`permissions: contents: read`) and a job timeout (15 minutes; 20 for the macOS/Git Bash job).

The script then `cd`s into the target and continues the regular setup flow. At the end, the user is asked whether to delete the original folder — a safety check verifies that the folder still looks like a cephalo template before deleting.
- **Edge cases handled:**
  - Target path does not exist: created (including missing parent directories).
  - Target path is a non-empty directory: interactive confirmation required; non-interactive mode refuses and exits 2.
  - Target path equals current location: falls back to "proceed here" with a note.
  - Target path is an existing file (not a directory): exits 2 with an error.
- **`--help`** text in `setup.sh` updated to document the `--target` flag with examples.

### Changed

- **Setup prologue** now implicitly confirms to the user that the project will be created in the location they chose, reducing the "wait, where are my files?" moment that motivated this release.

### Rationale

The original design assumed users would work inside the extracted cephalo folder. In practice, people extract to Downloads and then ask where their thesis is. The new target flow lets users pick a sensible location (e.g., `~/Documents/Bachelorarbeit_KMU_OSS`) at setup time, without breaking the "agents and project content in the same directory" invariant that Claude Code requires.

## [3.0.0] — 2026-04-21

Initial open-source release of cephalo. Rewrite of an institution-specific, German-language v2 predecessor into an institution-agnostic, English-language form.

### Added

- 10 agent definitions (orchestrator, orchestrator-longform, orchestrator-defense, research, writer, source-verifier, format-verifier, style-resolver, methods, data).
- 8 workflow configurations (seminar, presentation, bachelor flat+longform, master flat+longform, proposal, defense).
- 4 checklists (precheck, format rules, consistency, plagiarism protection).
- 5 templates (status, decisions, handover, feedback log placeholder, styleguide).
- 4 utility scripts (style guide extraction, DOCX post-processing, abbreviations extraction, bibliography check).
- Documentation (QUICKSTART, error catalog, phase separation, long-form structure, multi-project structure, reference management, git introduction).
- Setup scripts for Linux/macOS (`setup.sh`) and Windows (`setup.ps1`).

### Design principles (carried over from v2)

- **Institution-agnostic via `style-resolver`** — citation conventions are extracted from institutional guidelines at setup, not hardcoded in prompts.
- **Phase separation** — content work (Phase A, capable models) and formatting work (Phase B, fast models) run with different agent activation, reducing cost ~60-70% against naive use throughout.
- **Self-contained agents** — Claude Code sub-agents cannot read `CLAUDE.md`, so each agent declares its own file paths and mandatory-read behavior.
- **Structural isolation of guidelines** — the `_guidelines/` underscore prefix keeps institutional rule documents separate from citable source literature.
